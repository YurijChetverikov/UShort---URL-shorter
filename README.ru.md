# UShort — высокопроизводительный сократитель ссылок и система аналитики

[![License: MIT](https://img.shields.io/badge/License-GPL_3.0-blue.svg)](LICENSE)

[English](README.md) | **Русский**

Лёгкий и высокопроизводительный сократитель ссылок на ASP.NET Core 10 и Vue.js 3. Система не только сокращает ссылки и мгновенно генерирует QR-коды, но и асинхронно собирает подробную аналитику по переходам и созданию ссылок с помощью конвейера на основе in-memory канала и высокоскоростной бинарной вставки в PostgreSQL.

## 🚀 Ключевое

* Мгновенное сокращение ссылок и генерация QR-кодов: длинные URL превращаются в короткие читаемые ссылки с автоматически созданными QR-кодами для удобного перехода с мобильных устройств.
* O(1)-проверка дубликатов по хэшу: система не хранит повторяющиеся длинные URL — SHA-512 хэш индексируется в отдельной таблице поиска, и при совпадении сразу возвращается существующий ID короткой ссылки.
* Неблокирующий конвейер аналитики: метрики обрабатываются вне основного потока через `System.Threading.Channels`, что обеспечивает почти нулевые накладные расходы на задержку редиректа.
* Высокопроизводительная пакетная обработка: события аналитики сбрасываются в PostgreSQL через `COPY BINARY` вместо традиционных `INSERT`.
* Геолокация по IP: определяются континент, страна, город, точные координаты и радиус точности с помощью локальной базы MaxMind GeoLite2 City.
* Полное журналирование событий: логируются как создание ссылок, так и переходы — включая неудачные попытки открыть недействительные или битые короткие ссылки.

### Backend
* Framework: .NET 10 / ASP.NET Core
* PostgreSQL 18

### Frontend
* Framework: Vue.js 3
* UI и стили: Bootstrap 5

## 🚀 Производительность

Замеры локально на многоядерной машине с [`hey`](https://github.com/rakyll/hey) (`-c 50`, localhost, без TLS):

| Метрика               | Значение        |
|-----------------------|-----------------|
| Обработано запросов   | 1 000 000       |
| Общее время           | 16.27 с         |
| Пропускная способность| **~61 400 RPS** |
| p50 latency           | 0.7 мс          |
| p99 latency           | 3.4 мс          |
| Max latency           | 130 мс          |
| Доля ошибок (5xx)     | **0**           |

На VPS, близком к продакшену (1 vCPU / 512 MB RAM), сервис выдерживает ~782 RPS на коротких всплесках; при длительной нагрузке ограничением является доступная RAM, а не код приложения.

Самая крупная оптимизация — замена `INSERT` на каждый запрос на пакетную запись через `COPY BINARY`. До этого изменения на том же VPS p99 составлял ≈ 1 с, а под нагрузкой наблюдались многсекундные паузы.

## 🏗️ Архитектура и производительность

![Scheme](/img/scheme.jpg)

### 1. Асинхронный конвейер событий (System.Threading.Channels)
Если записывать аналитику синхронно при каждом переходе или создании ссылки, это замедлит HTTP-ответ. Чтобы редиректы оставались максимально быстрыми, входящая телеметрия публикуется в фоновый канал и асинхронно обрабатывается отдельным worker-сервисом.

### 2. Быстрая пакетная запись (COPY BINARY + батчинг)
Вместо выполнения одиночных `INSERT` на каждое событие:
* события буферизуются в памяти и сбрасываются либо раз в 1 секунду, либо когда очередь достигает 100 записей;
* буфер записывается в PostgreSQL через нативный `NpgsqlBinaryImporter` (`COPY ... FROM STDIN (FORMAT BINARY)`), что позволяет обойти накладные расходы на разбор SQL и достичь максимальной скорости записи.

### 3. Быстрая проверка дубликатов ссылок через SHA-512
Перед сохранением нового URL:
1. Система вычисляет SHA-512 хэш целевого длинного URL.
2. Выполняется быстрый поиск по таблице соответствия SHA-512 → LinkID.
3. Если совпадение найдено, система сразу возвращает существующую короткую ссылку, не создавая новых записей.

## 📊 Аналитика и схема событий

Каждое взаимодействие с системой записывает стандартизированную строку события со следующими телеметрическими данными:

| Колонка | Описание |
| :--- | :--- |
| Тип события | 'R' — переход (redirect), 'C' — создание ссылки |
| ID ссылки | ID целевой ссылки (-1, если короткая ссылка была недействительной/битой) |
| User-Agent | Заголовок user-agent клиентского устройства и браузера |
| ID континента | ID континента по MaxMind GeoLite2 (если определён) |
| ID страны | ID страны по MaxMind GeoLite2 (если определён) |
| ID города | ID города по MaxMind GeoLite2 (если определён) |
| Координаты | Широта и долгота (если определены) |
| Радиус точности | Радиус точности геолокации |
